## 目录结构

```
<工作目录>/
├── README.md                 ← 本文件，总入口
├── 使用手册.html              ← 小白版图文手册
├── 更新知识库.cmd              ← 双击这个更新数据
├── cookie.txt                ← 登录凭证（会过期，不进打包）
├── kb_state.json             ← 增量更新状态
│
├── tgb_posts/                98 篇主帖正文
├── tgb_replies/              98 篇帖子的楼主跟帖（全量）
├── tgb_replies_digest/       跟帖精华版（过滤掉寒暄）
├── tgb_replies_qa/           跟帖对话版（楼主回答 + 网友提问，29MB）
├── tgb_replies_index.md      跟帖总索引（每篇的条数对照表）
├── 跟帖实战速查手册.md         374 条实战原话，按 15 个主题分章
├── 个股与题材速查索引.md        291 只个股 / 55 个题材 / 30 个月份
├── tgb_all_topics.txt        主帖列表（含每篇全站跟帖总数）
└── .zip     移植包（12.8MB，含对话版）

~/.workbuddy/skills/tgb-jian-gu-qi-yi/     ← 安装后的技能目录
├── SKILL.md                  技能说明（AI 读这个）
├── PORTING.md                移植指南
├── 使用手册.html
├── install.cmd               新电脑双击这个
├── scripts/                  抓取与构建脚本
└── references/               数据（与上面工作目录的内容同步）
```

> **两种目录的关系**：工作目录是「加工车间」，技能目录是「成品」。
> 跑完更新后数据会从工作目录同步进技能目录，所以同一个内容会存两份。
> 换到新机器时可以用【原地模式】只保留一份，见 `PORTING.md`。

## 五种数据，什么时候用哪个

| 数据 | 内容 | 用在哪 |
|---|---|---|
| `跟帖实战速查手册.md` | 374 条原话 / 15 主题 | **方法论问题先翻这个**。低吸、卖点、仓位、做T、洗盘、见顶、心态…… |
| `个股与题材速查索引.md` | 291 只个股 / 55 题材 / 30 月 | **问「某只票 / 某个题材他怎么说」先翻这个**，附提及次数与代表原话 |
| `replies_qa/` | 楼主 50,929 + 网友 118,333 条 | **回答看不懂在回应什么时查这个**。网友提问和楼主回答按楼层交织，41,185 条带「楼主回复了这条」标记 |
| `replies_digest/` | 25,074 条精华 | grep 检索的**日常首选**，已过滤「谢谢师父」「早」这类纯寒暄 |
| `replies/` | 50,833 条跟帖全量 | 做**重要判断**时兜底检索，避免漏掉短而有价值的提示 |
| `posts/` | 98 篇主帖正文 | 看**完整方法论**、系统性的思路推演 |

**为什么需要对话版？** 只收楼主发言时，粉丝问了什么是拿不到的——
回复里那个 `> 昵称 / > 时间` 只带名字和时间，**不带提问原文**。
结果很多回答脱离提问完全读不懂：

> 网友「尘世小顽童888」14:42：师父 亚盛尾盘资金才开始维护想拉板，它不能封板对于板块影响大吗…
> **★见股起意 15:04**：类似于昨天回复的金健的观点。

没有上一句，那个回答就是一句废话。对话版把提问也收进来，还标出哪些是楼主回答过的。

**为什么跟帖比主帖值钱？** 主帖是他事后整理的「方法论」，规整但抽象；
跟帖是他盘中的实时判断，带具体点位和仓位。比如：

> 早盘第一个低吸点在 -2-3%，紧接着大盘下杀，-3%-6% 低吸都没性价比，-7-8% 才有低吸性价比。

这种话只有跟帖里有。

## 更新数据

### 最简单的办法

双击 `更新知识库.cmd`，等它跑完，按任意键关掉。正常情况**一两分钟**。

### 命令行

```bash


"$PY" "$SKILL/scripts/update_kb.py"
```

### 常用参数

| 参数 | 作用 |
|---|---|
| `--check` | 只体检：cookie 是否有效、有几篇待更新，不抓数据 |
| `--force` | 全量重抓（≈5,700 页 ≈35 分钟），忽略增量判定 |
| `--workers 8` | 并发数，默认 4 |
| `--tail-pages N` | 已抓过的帖子重抓尾部多少页，默认 2 |
| `--posts-only` / `--replies-only` | 只跑主帖 / 只跑跟帖 |
| `--no-sync` / `--no-package` | 不同步到技能目录 / 不重新打 zip |
| `--inplace --root <技能目录>` | 原地模式，数据只存一份（新机器用） |
| `--root D:/xxx` | 换工作目录 |
| `--cookie-file <路径>` | 指定 cookie |

### 增量判定是怎么做的

主帖列表页每篇标题后面有个 `(15520)`，那是**全站跟帖总数**。
把它记进 `kb_state.json`，下次跑时比对：

- 出现新 slug → 新帖，抓正文 + 抓全部跟帖页
- 数字变了 → 只重抓「最后 2 页 + 所有新增页」，再与本地条目按
  `(时间, 内容前50字)` 去重合并

所以正常情况下一次更新只要几十个请求，不用再等 35 分钟。

状态文件删了也没关系——会自动从已有 md 的「原帖：」行反推恢复，
不会误判成 98 篇全量新帖。

### 安全阀

`--force` 全量重抓时，如果新结果比旧数据少 10% 以上，
判定为中途请求失败，自动回滚成「旧 ∪ 新」并集，不会把历史数据写没。

### cookie

登录态会过期，脚本第 1 步就会校验，失效时明确报错。

重新获取：浏览器登录  → F12 → Network → 任选一个请求 →
复制 Request Headers 里的整条 `cookie` → 存到 `cookie.txt`（一行）。

也可以 `--cookie-file <路径>` 或设环境变量 `TGB_COOKIE`，不用改代码。

## 换电脑

```bash
# 新电脑上
解压 .zip
双击 install.cmd          # macOS / Linux：python3 scripts/install.py
```

安装器会自动：装到 `~/.workbuddy/skills/` → 检查 Python，缺 `requests` 就建
独立 venv 装上 → 写路径配置 → 生成 `更新.cmd` → 跑一次自检。

**只想读、不想抓**：解压后把目录整个丢进 WorkBuddy 的 `skills/` 下重启即可，
不需要 Python，也不需要 cookie。

细节见 `PORTING.md`。

## 检索技巧

### 让 AI 帮你查（推荐）

直接在对话框问，它会去翻这些文件。问得越具体越好：

| 差 | 好 |
|---|---|
| 教我炒股 | 红宝丽这种已经翻倍的票，什么时候该跑？ |
| 怎么卖？ | 跌破五日线要割吗，他之前是怎么处理的？ |
| 讲讲低吸 | 低吸完如果被套了怎么办 |

**追问比另起新问题更有效** —— 上下文还在，答案会更贴。

### 自己翻索引

`个股与题材速查索引.md` 是查「某只票 / 某个题材」的快捷入口：

- 想知道他聊过哪些票、每只聊了多少次 → 第一节表格（含首尾日期、涉及哪几篇主帖）
- 想看他某只票的代表原话 → 第二节（按提及次数取前 40 只）
- 想看某个题材的活跃时期 → 第三节
- 想了解某个阶段他在想什么 → 第五节月度统计 + 第六节近 12 个月原话

### 自己 grep

```bash
# 精华检索（噪音少，首选）
grep -rn "航天发展" tgb_replies_digest/

# 全量检索（做重要判断时用，避免漏）
grep -rn "破五日线" tgb_replies/

# 只看哪些帖子里提到过
grep -rl "渡劫" tgb_replies_digest/

# 主帖里找系统性论述
grep -rln "要信早信" tgb_posts/

# 看某篇帖子的全部跟帖
cat "tgb_replies/024_我说要去海南玩_跟帖.md"
```

先翻 `tgb_replies_index.md` 有每篇帖子的跟帖条数对照表，能快速定位哪篇内容最多。

## 已知限制

- **截图拿不到** —— 博主的图全部丢失，只保留文字。跟帖里偶尔会有「见图」这种指涉。
- **跟帖是一对一答疑** —— 大量内容是回应某个粉丝的具体提问，
  上下文在引用里。引用文本有保留，但**务必结合引用理解，别断章取义**。
- **精华版是规则过滤的** —— 靠关键词 + 长度（≥20 字）自动判定，
  可能漏掉个别短但有价值的盘中提示。做重要判断时建议全量版也检索一遍。
- **个股索引是规则提取的** —— 靠「后缀规则 + 人工核定词表」双源识别并做了引导词剥离。
  高频段（≥5 次）可信度高；**低频附录（2-4 次）可能混入口语词**，引用前回原文核对。
- **观点有强时效性** —— 内容跨 2024-2026，很多判断跟当时的市场环境绑定。
- **「只看该作者」接口不可用** —— 那是网页端的积分付费功能，
  积分耗尽会返回 HTTP 200 的 `淘股吧_积分不够` 页面（静默失败）。
  本项目改用免费的分页接口 + 本地筛选，不消耗积分。
